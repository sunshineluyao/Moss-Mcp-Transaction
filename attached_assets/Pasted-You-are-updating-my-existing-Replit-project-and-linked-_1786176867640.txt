# Final MVP Goal

Transform the current mock-first transaction lifecycle demo into one truthful, narrow, live end-to-end experience:

> A user enters a native MON transfer intent. An A2A agent applies a Moss-derived safety skill, invokes a real custom MCP server, checks the unsigned transfer against live Monad Testnet state, and returns an explainable review artifact. Nothing is signed or broadcast.

The final visible architecture is:

```text
React UI
  → thin preview API
  → official A2A client
  → Monad Preview A2A Agent
  → official MCP client over stdio
  → custom Monad Testnet Preview MCP server
  → live Monad Testnet RPC
```

The application must demonstrate all five requested layers:

1. Monad Testnet
2. Agent Skills
3. A2A
4. Agent Stack compatibility
5. MCP

Use the official `@modelcontextprotocol/sdk`. Run the custom MCP server over stdio and invoke it through a genuine MCP client. Do not bypass MCP by directly importing and calling the tool functions from the A2A executor.

MCP server identity:

```text
name: monad-testnet-preview
version: 1.0.0
transport: stdio
```

Expose four narrowly scoped tools:

1. `preview_discover`

   * Returns the one available action: native MON transfer preview.

2. `preview_load`

   * Returns the input contract, intent description, risk boundaries, network restriction, and safety rules.

3. `preview_action`

   * Validates addresses and decimal amount.
   * Constructs the unsigned transaction.
   * Does not query for or handle any secret.

4. `preview_simulate`

   * Requires the exact output from `preview_action`.
   * Queries live Monad Testnet state.
   * Returns network evidence, gas estimate, balance checks, warnings, and the final decision.

This sequence is inspired by Moss’s `discover → load → action → simulate`, but every UI and README reference must clearly identify it as the custom Testnet adapter.

The A2A agent must call the tools through the MCP client in that exact order. Record a real trace containing:

* MCP server name/version
* Transport
* Tool name
* Start/end time or duration
* Success/failure
* Sanitized input summary
* Data source

Do not fabricate a successful trace if a tool was not called.
